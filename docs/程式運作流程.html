WdBot.Service · .NET 10

WD 機器人服務運作流程

依照目前的程式碼整理。機器人服務從 BOT 管理後台微服務取得設定，自動登入 WD 遊戲、維持聊天連線，把玩家私訊轉給微服務，再依微服務的指令私訊玩家；也能回報公頻線上名單，並確保一個廳只有一個機器人。

元件職責
WebSocketBackendLink主動連線微服務；接收設定與送訊指令；回報私訊、送出結果、狀態、公頻名單
BotManager依設定新增、停止、重啟機器人；把 message.send 轉給對應的機器人
ChannelRegistry記錄每個公頻由哪個機器人佔用，確保一廳一機器人
BotInstance單一機器人的完整生命週期，串起下面四個元件
GameSession帳密登入、刷新 token、API 回 2029 時自動刷新後重送
ChatSupervisor維持聊天 WS 連線：斷線重連、輪替網址、依踢線原因決定是否重連
PrivateMessageSender依序送出私訊：200 字拆段、間隔 2.1 秒、太快時重試
ChannelMemberScanner用 opcode 9 翻完公頻所有分頁

  F -->|"新的 bot_id"| I["建立機器人並啟動"]

  L -->|"致命錯誤碼"| ERR["error：停止"]
  L --> P["取得本人資料 getPlayerInfo"]
  P --> C{"聊天權限開啟？"}
  C -->|"否"| ERR
  C -->|"是"| R["同時執行"]

  R --> W["聊天連線（第 4 節）"]
  T -->|"重新登入也失敗"| ERR
  W -->|"被踢：7002、7003、7004、7006"| ERR
  T -->|"暫時性錯誤"| RT["reconnecting<br/>等 5 秒起，每次加倍，最多 300 秒"]
  W -->|"暫時性錯誤"| RT
  RT --> L
  • 登入的致命錯誤碼：2001 參數驗證失敗（帳號密碼格式不符）、2002 帳號找不到、2003 登入失敗、2023 密碼錯誤太多次、2024 預約刪除中、2041 帳號密碼不吻合、2045 帳號無法使用、4038 停權
  • 進入 error 後機器人就停止。後台修正設定後，對同一個 bot_id 再送一次 config.upsert，就會重新啟動
  • 送私訊時要帶的暱稱、頭像、頭像框、對話框 ID，都從登入與本人資料取得
  • 等級 0（沒綁手機）的帳號不會停止：照樣登入、進公頻、收私訊、掃描名單，online 狀態的 detail 會註明無法發言；送私訊時遊戲端會回 5008

04聊天連線與一廳一機器人

flowchart TD
  A["連聊天 WS<br/>chat_ws_url?token=access_token"] -->|"失敗"| A1["換下一條網址、刷新 token<br/>等 1–60 秒（維護中至少 120 秒）"]
  A1 --> A
  A -->|"成功"| B["收到 opcode 7<br/>已加入公頻，取得 channel_id"]
  B --> C{"這個廳已經有<br/>其他機器人？"}
  C -->|"沒有"| D["佔用此廳<br/>回報 online 與 channel_id"]
  D --> E{"有開啟<br/>scan_channel_players？"}
  E -->|"是"| F["掃描公頻名單（第 6 節）"]
  E -->|"否"| G["收發私訊"]
  F --> G
  C -->|"有：撞廳"| H{"已連續撞廳 10 次？"}
  H -->|"否"| I["斷線，5–7.5 秒後重連"]
  I --> A
  H -->|"是"| J["waiting_channel<br/>下線 300 秒後重新嘗試"]
  J --> A
  G --> K{"連線結束原因"}
  K -->|"一般斷線"| K1["釋放廳，1 秒起退避重連"]
  K -->|"7000 同帳號在別處連線"| K2["釋放廳，等 300 秒"]
  K -->|"7001 強制踢出"| K3["釋放廳，等 30 秒"]
  K -->|"7005 維護"| K4["釋放廳，等 120 秒"]
  K -->|"7002、7003、7004、7006"| K5["error：停止"]
  K1 --> A
  K2 --> A
  K3 --> A
  K4 --> A
  • 公頻由遊戲伺服器隨機分配，無法自選，也沒有離開公頻的指令。撞廳時只能斷線重連，讓伺服器重新分配
  • 撞廳重試期間仍可收私訊；waiting_channel 期間處於下線狀態，私訊收不到，message.send 會回 -2
  • 可以在 appsettings.json 設 Bot:OneBotPerChannel = false 關閉這個機制
兩個前提：佔廳的對照表只存在單一服務程序中，所以只能執行一個機器人服務實例；另外，重連後伺服器要確實可能分到不同的廳，這點需要向遊戲方確認。

05私訊收發

sequenceDiagram
  autonumber
  participant P as 玩家
  participant WS as WD 聊天 WS
  participant B as 機器人
  participant M as 微服務
  P->>WS: 私訊機器人
  WS->>B: opcode 2 推送
  Note over B: 略過自己發的訊息<br/>依 message_id 去重
  B->>M: message.received
  B-->>WS: opcode 6 已讀（auto_mark_read 開啟時）
  M->>B: message.send（request_id、to_player_id、text）
  Note over B: 放入送出佇列<br/>超過 200 字拆成多則
  loop 每一則
    Note over B: 與上一則間隔至少 2.1 秒
    B->>WS: opcode 2（帶 trace_id、暱稱、頭像、對話框）
    WS-->>B: 同 trace_id 的回包（最多等 10 秒）
    alt 回 5007 或 2044
      Note over B: 退避後重試，每則最多 4 次
    end
  end
  B->>M: message.send_result（success、message_ids 或 err_code）
  WS->>P: 玩家收到訊息
  • 回覆玩家和主動私訊都用 message.send；主動私訊只是不帶 reply_to_message_id
  • 機器人沒有連線時，送出佇列最多等 30 秒，仍未恢復就回 -2
  • 等待回包逾時（-3），或等待時斷線（-6），都無法確定訊息是否送達，所以不會自動重送，交給微服務判斷

06公頻名單掃描

只有 scan_channel_players 為 true、而且佔到廳的機器人才會掃描。

sequenceDiagram
  participant B as 機器人
  participant WS as WD 聊天 WS
  participant M as 微服務
  WS->>B: 連線後主動推送 opcode 7（已加入公頻）與 opcode 9（成員列表第一頁），順序不固定
  Note over B: 確認佔到廳後處理推送的第一頁
  opt next_cursor 不是空字串（超過 100 人）
    B->>WS: opcode 9（帶 cursor，每頁間隔 200 毫秒）
    WS-->>B: 下一頁，直到 next_cursor 為空字串
  end
  WS->>B: 取得名單期間收到 opcode 17
  Note over B: 先暫存
  B->>M: channel.snapshot（完整名單，不含自己）
  B->>M: 補送暫存的 channel.members_changed
  WS->>B: opcode 17（伺服器每 3 秒彙整一次）
  B->>M: channel.members_changed（joined、left）
  M->>B: message.send（微服務決定要私訊誰）
  opt 遊戲方再次推送 opcode 9
    B->>M: channel.snapshot（以新名單取代）
  end
  opt 超過 10 分鐘沒收到 opcode 9 推送（Bot:ChannelRescanMinutes）
    B->>WS: opcode 9 從第一頁主動掃描
    B->>M: channel.snapshot（新的完整名單）
  end
  • 名單以遊戲方推送為主：連線後伺服器會主動推送 opcode 9（第一頁），機器人不另外送請求；只有超過 100 人（next_cursor 不是空字串）時，才主動要剩下的頁面湊成完整名單。之後靠 opcode 17 維護增減
  • 超過 10 分鐘（Bot:ChannelRescanMinutes，0 表示關閉）都沒收到 opcode 9 推送，才主動從第一頁掃描一次
  • 每次重連都會重新建立名單，因為重連後可能換到別的廳。微服務收到新的 snapshot 時，應該取代該機器人的舊名單
  • 機器人自己也以「完整名單＋增減」維護目前在線名單，log 會印出目前在線人數；名單同時寫成實體檔，檔名依大廳編號區分：logs/roster/{env}/channel-{大廳編號}.json，可以直接打開查看；離開或換廳時刪除舊大廳的檔案（Bot:WriteRosterFile，預設開啟）
  • 掃描失敗時不送 snapshot，bot.status 維持 online 並在 detail 說明原因，之後照常回報成員異動
  • 要私訊誰、是否已經私訊過，都由微服務判斷，機器人不記錄

flowchart TD
  A["呼叫 App API<br/>每 60 秒最多 190 次"] --> B{"error_code"}
  B -->|"1000"| OK["成功"]
  B -->|"2044 呼叫太頻繁"| C["等 retry_after_seconds 後重試<br/>最多 3 次"]
  C --> A
  B -->|"2029 token 失效"| D["用 refresh_token 刷新"]
  D -->|"成功"| E["用新 token 重送一次"]
  D -->|"網路逾時"| D1["50 秒內以同一個 refresh_token 重送<br/>最多 4 次"]

  • 聊天 WS 只在建立連線時驗證 token，所以 token 更新不會讓已建立的聊天連線斷線

08與微服務斷線時

flowchart TD
  A["與微服務斷線"] --> B["機器人在遊戲中照常運作"]
  B --> C["私訊、送出結果、公頻名單<br/>放入上行佇列，上限 10,000 則<br/>滿了丟棄最舊的"]
  B --> D["狀態只保留每個機器人的最新一筆"]

  E --> F["重連成功，送 hello"]

  • 機器人服務重啟時，佇列中還沒送出的私訊會遺失

09重要參數

appsettings.json 可調整

設定預設說明
Backend:Urlws://localhost:5080/…微服務 WebSocket 網址（目前是佔位值）
Backend:ApiKey空連線時帶的 X-Api-Key
Backend:OutboxCapacity10000斷線期間的上行佇列上限
Bot:TokenRefreshIntervalMinutes50主動刷新 token 的間隔（分鐘）
Bot:DuplicateLoginCooldownSeconds300被 7000 踢線後等多久重連
Bot:MaintenanceBackoffSeconds120維護中（7005）等多久重連
Bot:ChatReconnectMaxSeconds60聊天重連的最長等待
Bot:SendReplyTimeoutSeconds10送私訊後等回包的時間
Bot:SendQueueCapacity1000每個機器人的送出佇列上限
Bot:RestartMaxDelaySeconds300暫時性錯誤後重新登入的最長等待
Bot:OneBotPerChanneltrue是否啟用一廳一機器人
Bot:ChannelCollisionMaxAttempts10連續撞廳幾次後下線等待
Bot:ChannelCollisionRetrySeconds5撞廳後隔幾秒重連（另加 0–50% 隨機）
Bot:ChannelWaitingRetrySeconds300下線等待多久再試
FileLogging:Directorylogs一般 log 的資料夾（每天一個檔案）
FileLogging:MessageDirectorylogs/messages訊息內容 log 的資料夾，依 bot_id 分子資料夾（私訊 messages-*.log、公頻 channel-*.log）
Logging:LogLevel:WdBot.Messages.PrivateInformation（本機測試為 Debug）設為 Debug 才會寫私訊內容 log；log 輸出位置、格式與保留天數（30 天）見 nlog.config
Logging:LogLevel:WdBot.Messages.ChannelInformation（本機測試為 Debug）設為 Debug 才會寫公頻內容 log，可與私訊分開開關
Bot:ChannelRescanMinutes10超過幾分鐘沒收到遊戲方推送的 opcode 9，才主動掃描一次公頻名單；0 表示不主動掃描
Game:UnityVersion2022.3.20f1真的 App 使用的 Unity 版本，用在 Header 的 {unity_version}；要以抓到的封包為準
Game:RequestHeaders模擬 Unity 安卓 App送給遊戲方的 Header（App API 與聊天 WS），詳見 README
Bot:WriteRosterFiletrue是否把在線名單寫到 logs/roster/{env}/channel-{大廳編號}.json

依遊戲規格寫在程式中的固定值

項目值依據
App API 頻率190 次／60 秒規格上限 200 次，保留餘量
私訊間隔2.1 秒規格每 2 秒 1 則
私訊單則長度200 字規格上限 200 字
公頻翻頁間隔200 毫秒規格每條連線每秒最多 50 則指令
